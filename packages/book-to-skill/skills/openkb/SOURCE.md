## Provenance: derived, not vendored

`SKILL.md` is original prose. No upstream file is copied into this directory, so there is
no third-party tree here to keep in step.

The reason is structural rather than stylistic. `upstream.json` pins a sha256 for every
file under `vendor/book-to-skill/`, and `test/package.test.ts` asserts that the manifest
equals a listing of that directory exactly. A second vendored upstream under `vendor/`
would either break that equality or force the manifest to describe two unrelated projects
under one `source` record. Deriving avoids both, and it matches how `.omk/skills/
omk-higgsfield` handles an external CLI.

## What was taken

The interface facts only, pinned to the commit above:

- The wiki layout OpenKB compiles (`wiki/index.md`, `concepts/`, `entities/`,
  `summaries/`, `sources/`), the `sources:` frontmatter field, and wiki-relative
  `[[wikilink]]` resolution.
- The command surface used for read-only navigation (`openkb status`, `openkb list`,
  `openkb query`) and the `Knowledge base: <path>` line `status` prints.
- Which commands mutate a knowledge base, spend model budget, or start a long-lived
  process (`add`, `remove`, `lint --fix`, `init`, `use`, `chat`, `watch`).

A wrapper that states these differently is simply wrong, which is why they are pinned.

## What was deliberately left out

- **The Skill Factory (`openkb skill new`).** This package already compiles documents into
  provenance-tracked skills through `/book-to-skill-compile`, and it verifies them with
  `/book-to-skill-verify`. Routing the same request two ways is the split this bundle
  exists to prevent, so `SKILL.md` names the Skill Factory once, to redirect away from it.
- **Generators unrelated to retrieval** — `visualize`, `deck`, the REST API, and the
  Knowledge Workbench web UI. They produce artifacts, not answers, and none of them is
  reachable from a question about the user's knowledge base.
- **Upstream's host-specific tool tables.** The upstream skill maps its verbs onto Claude
  Code and Gemini CLI tool names; this wrapper states the verbs and lets OMK's own tool
  surface answer for them.
- **`.claude-plugin/marketplace.json` and the deck/HTML-critic skills.** They belong to
  upstream's own distribution channel and have no OMK counterpart.

## Relationship to OMK's OpenWiki

Unrelated, despite the similar name. OMK's `openwiki/` corpus is generated by the npm
package `openwiki` from **source code**; OpenKB compiles **documents**. Neither replaces
the other, and this skill does not read or write `openwiki/`.
